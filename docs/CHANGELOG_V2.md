# 改訂履歴｜v1 → v2
改訂日: 2026-10-02。v1は参照専用で保管し、今回の指示と同時に有効化しない。元のPDF/Word/MD/ZIPは上書きしていない。

## 今回確定した依頼
「iPhoneでも使え、かつ基本無料運用がぜんてい」
「コーデックスに渡してからは確認と判断に徹するポジションで参画が理想」

| 項目 | v1 | v2 | 根拠と影響 |
|---|---|---|---|
| 対象OS | Android初版 | iPhone / Android | ユーザー確定要望 |
| 配布 | Google Play中心 | PWA / 無料静的配信 | ストア登録費を初版の前提にしない |
| UI/実装 | Kotlin / Compose | React / TypeScript / Vite | 両OSの単一コードを基本。互換性は試験 |
| 撮影 | ML Kit Scanner | ブラウザーからOS撮影/画像入力 | 原本Fileを先に保存。API制約は実測 |
| 切り抜き | SDK内の自動検出・微調整 | 手動4点が必須、自動候補は品質条件付き | 安定した手動を成立させてから自動化 |
| 再編集 | 切り抜き済み返却画像が基準 | ブラウザーが受け取った原本を保存 | 保持範囲内で最初の切り抜きからやり直せる |
| データ管理 | Room＋専用ファイル | IndexedDB＋Blob | 保存・更新・多重起動をブラウザー向けに再設計 |
| バックアップ | PDF外部保存、編集情報の復元は範囲外 | PDF外部保存＋日付単位の復元パック必須 | PWAの消失リスク対策。全編集履歴の完全保存は対象外 |
| PDF | Android PdfDocument | pdf-lib候補 | 全体メモリを測る。10ページを初期目標、20は拡張試験 |
| 添付 | FileProvider / Sharesheet | 実FileをWeb Shareへ渡す | 生成後の明示共有ボタン。送信成功とはしない |
| 更新 | Play更新 / Room migration | SWの更新案内 / IDB migration | 強制再読込禁止。同一URL維持・復元を重視 |
| Codex開始 | 監査のみで停止 | 監査→実装→検証→修正を継続 | 毎工程の判断負荷を減らす。不可逆/外部操作は承認 |
| 開発環境 | Android SDK/JDK/Gradle | Node＋ブラウザー中心 | 初版にMac/Xcode購入は前提なし。iPhone実機確認は必要 |
| 役割 | 各工程の開始承認 | 監督判断カードで必要時だけ確認 | 認証・公開・実物画質など人にしかできない点を限定 |

## 維持した設計
1枚ごとに保存、PDFは必要なときに選択ページで作る。同じ日でも提出先ごとに分けられる。ファイル名と内部IDを分離し、修正で過去PDFを勝手に変えない。生成AIで文字を描き替えない。共有と送信を区別し、顧客文書は外部AI/サーバーへ送らない。

## 原文・事実・提案・未検証
ユーザーが明示した3条件は確定。PWA/Cloudflare/ライブラリはその条件からの設計提案。無料枠やAPIの確認は根拠台帳。画質・速度・全機種対応・実装の品質は未検証であり、完成した設計と完成したアプリを混同しない。
