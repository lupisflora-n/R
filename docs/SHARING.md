# R のスマホとPCの共有手順

GitHubのリポジトリをコードの共有元にします。会話履歴、未コミットのファイル、実行中のプロセスはGitで同期されません。端末を切り替える前に変更をコミットし、GitHubへ反映してください。

## 今回のクラウド実装をWindowsへ移す

2026-10-03時点でGitHubのoriginは未設定です。日付スキャンv2のローカル実装は `codex/docscan-v2` ブランチにあります。最新の `R.bundle` は全Git履歴を含む引き継ぎファイルです。以前保存した古いbundleとは区別してください。

Gitが使えるWindowsターミナルで、最新のbundleを置いたフォルダから次を実行します。既存のRフォルダを上書きせず、新しい場所で行ってください。

```powershell
git clone .\R.bundle R
cd R
git switch codex/docscan-v2
```

WindowsのCodexでこのRフォルダを開き、「STATE.mdから続けて。まずブラウザー検査を実行し、失敗を修正して」と依頼します。Node24.3以降があれば、アプリのビルドと純粋処理テストは追加取得なしでできます。Playwrightブラウザー検査と実機検査は別途必要です。

bundleは引き継ぎ時点のコピーであり、自動同期ではありません。継続的なPC/クラウド共有は、GitHub認証とoriginを設定してから使います。下記のGitHub手順は、その設定後の運用です。

## GitHubの初期設定

想定の共有先は `https://github.com/lupisflora-n/R` です。リポジトリの存在、アクセス権、初期ファイルの反映を確認してから利用してください。

非公開リポジトリを作り、CodexのGitHub接続にRへのアクセスを許可します。作成権限や設定画面へのアクセスが必要な操作は、アカウント本人の画面で行います。

## スマホからクラウドで作業する

1. Codexのクラウド作業画面でGitHub接続を設定し、Rを対象リポジトリとして選択します。
2. クラウド環境にRを紐づけます。後から依存ライブラリを追加した場合は、セットアップコマンドも設定します。
3. 「AGENTS.mdに従って、機能を実装し、必要な検証を行い、PRを作成して」と依頼します。
4. PRの変更内容を確認し、GitHubでマージします。

画面や機能の提供状況はアカウントによって異なります。このチャットのクラウド作業フォルダだけでは、今後のすべてのCodexタスクにRが自動選択されるとは限りません。

## PCで初めて開く

PCのネット接続があるときに、Gitをインストールしたターミナルで次を実行します。非公開リポジトリへのGitHub認証が必要です。パスワードやトークンをチャットへ貼る必要はありません。

```sh
git clone https://github.com/lupisflora-n/R.git
cd R
```

PCのCodexで、このRフォルダをプロジェクトとして開きます。既にRフォルダがある場合は上書きせず、内容とリモートを確認します。

## PCで作業を再開する

未コミットの変更がないことを確認し、最新のmainを取得して作業ブランチを作ります。

```sh
git status
git switch main
git pull --ff-only origin main
git switch -c codex/your-task
```

`your-task` は作業内容に置き換えます。作業後は対象ファイルを選んでコミットし、同じブランチをpushしてPRを作ります。

```sh
git add <変更したファイルのパス>
git commit -m "変更内容"
git push -u origin HEAD
```

## 作業を引き継ぐ

未完了の作業を渡す場合は、作業ブランチをpushし、ブランチ名、変更内容、検証結果、次に必要な作業を依頼文かPRに記録します。受け取る側はそのブランチを取得して作業します。

PCを起動していなくてもクラウドで開発できます。PC上のファイルを最新にするには、PCを起動してネットに接続し、pullする必要があります。
