# docPDF 固定編集画面の改修

2026-10-09 / codex/docpdf-lineのみ

## 本人の実機フィードバックと変更

前版build c9bba312e31d048dは本人提示のbuild.jsonと一致。操作中にボタンを探すためのスクロールで写真が見づらくなる、角のつまみが大きく隠れる、スライドが微量しか動かないと報告。

写真枠と操作を全画面に固定し、四隅/色調/明るさ/名前をタブで切替。上下の長い説明や比較画像の縦並びは廃止。原本比較は同じ写真枠の表示切替。下部に四隅決定/文書化/保存を置く。縦長・横長・回転後の画像を枠に収める。VisualViewportに合わせてキーボード表示時も画面高さを調整し、背景スクロールを閉じるまで停止する。

「文書化」は原本＋現在の四隅/回転/色調から処理する。新しい写真の既定は読みやすい白黒。「四隅を決定」も加工を同じ枠に反映。色調変更・回転はその場再処理、明るさ/コントラストは指を離した時に再処理。非同期処理中は案内と取消を表示するため、処理時間ゼロを保証するものではない。強い白黒は薄字が消える場合がある旨を表示。

ドラッグ中のDOM差込み直しを廃止。開始時の角と指の差分を、開始時の写真表示サイズで正規化する。掴んだ位置からジャンプせず、表示上の指の移動量と角の移動量を一致させる。保存座標の定義は回転前原本の0..1のまま。押す領域は44px、印は小さい十字と10pxの輪、番号は角の脇へ。矢印は2表示pxずつ移動。交差/範囲外の検証を維持。

保存は現在レシピの文書化プレビューと一致する場合のみ有効。保存時は全解像度の原本から処理し、DBコミット後に成功表示。原本/既存PDF/ごみ箱/バックアップの契約は保持。

## 検査とレビュー

合成40 PASS（連続ドラッグの差分/掴みオフセット/境界/表示倍率/固定写真枠の縦横比を追加）、構文20 PASS、静的配布4 PASS。npm run test:e2eはIPC拒否でBLOCKED/0 PASS。tests/browser.mjsへ12回連続moveの追従と再文書化/カラー変更を追加し、tests/mobile-quality.mjsへスクロール不要の寸法検査を追加したが、この環境で実行できていない。

既存UX担当エージェントによる読取りレビューで、画像上のラベル重なり、タブ別案内、ヘッダー比較ボタンのbusy無効表示を修正。レビューは実機検査の代替ではない。320〜412px、横向き、URLバー/ソフトキーボード、文字拡大、実タッチで検査が必要。
