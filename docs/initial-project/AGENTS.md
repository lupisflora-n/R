# R の作業ルール

- ユーザーへの説明は日本語で行う。
- README.md と docs/SHARING.md を確認してから作業する。
- 技術構成はまだ未決定。ユーザーの目的を確認し、必要な構成を選ぶ。
- 作業を始める前にGitの状態を確認する。未コミットの変更を上書きしない。
- GitHubをコードと開発方針の共有元とする。
- 通常の機能開発は作業ブランチで行い、変更内容と実施した検証を添えてPRにまとめる。
- ブランチ名は codex/ に短い作業名を続ける。別の作業があれば重複しない名前を使う。
- PCとクラウドで同じブランチを同時に編集しない。
- 変更に応じた検証を行い、実行していない検証は実行済みと書かない。
- APIキー、トークン、パスワード、実際の .env ファイルをコミットしない。
- セットアップ方法が変わったらREADME.mdまたはdocsを更新する。
