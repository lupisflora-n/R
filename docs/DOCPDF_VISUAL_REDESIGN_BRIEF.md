## 最新の依頼と変更範囲

本人の問題認識は「量産型っぽく、素人っぽく、安っぽい」。参考ブランドなし。色名の分類と既存配置を維持した初回A/B案では依頼の範囲を満たさない。本人が「ボタンの配置も全体の構成もデザインも全て一新」「機能的部分は保つ」と明示したため、配置固定という旧解釈を撤回する。

画面構成、ナビゲーション、ボタン配置、文字組み、余白、部品、配色、文言を再設計する。原本、保存形式、日付、白黒/カラー、白黒バランス1本、PDF/共有、削除/復元、バックアップ、LINE入口の機能契約は維持する。トリミング決定→調整→保存の順序と、編集を画面内で完結する条件も維持する。

最新の追加指示は「その日の紙を文書に」のような説明やボタン名に残るAI感をなくし、一般的なアプリの自然な表現にすること。宣伝文句、抽象的な励まし、常時表示の重複説明を除く。詳細は[文言方針](DOCPDF_UI_COPY.md)。

担当する職種はUI/UXデザイナーとアートディレクター。Codexはその責任範囲に沿って制作・検証・説明を進める。人間の専門家を雇ったとの主張や、人気・品質の未測定の保証はしない。

## 新しい画面構成

| 画面 | 構成 | 維持する機能 |
|---|---|---|
| 書類 | 書類一覧を主役に、日付切替、選択バー、下部の撮影/写真選択 | 日付、下書き、全選択、編集、削除、PDF対象選択 |
| トリミング | 写真を中心にした固定画面、四隅と微調整を手元に配置 | 四隅ドラッグ、角選択、方向調整、リセット、全体選択、決定 |
| 調整 | 大きい写真と下部の白黒/カラー・バランス・回転 | 原本比較、名前変更、白黒バランス1本、カラー、90度回転、保存 |
| PDF作成 | 順番とファイル名を専用画面で確認 | 同日最大10枚、並べ替え、名前、PDF生成 |
| PDF | 紙面確認を中心に、共有と保存を分離 | プレビュー、ページ切替、名前変更、共有、外部保存 |
| データ管理 | 書類一覧から分離した保存・復元の場所 | ZIP書出し/復元、ごみ箱、保存設定、ヘルプ |

今回は主経路6画面の方向性確認。PDF履歴一覧、日付選択、ごみ箱、名前入力、初回案内、空/未選択/処理中/無効/失敗/更新などの状態は採用方向の全体展開で補う。全画面・全状態の完成とは扱わない。

## 制作と検証

1. 本人は新しい構成と見た目を具体的な画面で判断する。仕様整理、文言、実装方式、検証はCodexが担当する。旧A/B質問は繰返さない。
2. 採用方向を残りの画面/状態へ展開する。Figmaの修正可能性が戻ったら最終文言と収まりを同期する。
3. 表示層・画面構成を実装し、既存処理・保存へ接続する。全機能への到達経路を確認する。旧配置との一致は受入条件にしない。
4. 画面サイズ、長い名前、コントラスト、44px操作領域、固定編集、既存データ、PDF/共有/復元の経路を検証する。ブラウザー/実機未検証を合格としない。
5. 専用LINE分岐だけ、既存公開承認範囲に沿って同URLへ反映する。main/codex/docscan-v2にマージしない。

FigmaはNoto Sans JP/Manrope、ローカルPNGはNoto Sans CJK/DejaVu Sans。ローカル収まり検査と目視はFigma最終スクリーンショットや実機操作検査とは別。顧客資料・実名・提供動画の私的な内容を使わず、書類見本は合成図形と文字だけ。ノード台帳はdesign/figma/redesign-state.json。
